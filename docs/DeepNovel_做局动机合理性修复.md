# DeepNovel 做局动机合理性修复 — Cursor 执行文档

> 修复"主角毫无价值时就有人精心设局陷害"的逻辑断裂问题。
> 核心原则：他人主动设局的前提是主角有被针对的价值或威胁，
> 否则施压应来自结构性困境、环境压力或意外，而非他人精心布局。

## 二、`prompts/creation/path_gen.py` 修改

### 2.1 在破局方式多样化要求之前，新增施压合理性约束

在 `PATH_GEN_USER_TEMPLATE` 里，找到破局方式多样化的段落，在其**前面**插入：

```
## 施压合理性约束（必须先通过此检查才能规划节点）

每个节点涉及"他人主动针对主角"的情节，必须通过以下逻辑自洽检验：

做局成本评估：
  这个局需要投入多少资源/风险/时间？
  （随手刁难 vs 精心布置是完全不同的成本等级）

做局收益评估：
  做局者能得到什么？
  直接收益：钱、权、物、信息、地位
  间接收益：消除威胁、借刀杀人、转移注意
  隐性收益：心理满足、立威、杀鸡儆猴
  注意：主角的人命/自由本身也是一种代价，
        关键是有没有比这个代价更大的利益驱使

合理性判断：
  做局成本 < 做局收益 → 合理，可以存在
  做局成本 > 做局收益 → 不合理，必须改写

常见不合理模式（必须避免）：
  ✗ 精心布置跨越多方的大局，只为让一个无关紧要的新人难堪
  ✗ 冒着极大风险去针对一个对自己毫无威胁也无利用价值的人
  ✗ 做局者没有任何已知动机，只是"莫名觉得主角碍眼"

合理的低成本做局示例：
  ✓ 管事顺手刁难新来的小卒——成本极低，收益是立威和心理满足，合理
  ✓ 同僚随手给新人使绊子——成本低，收益是减少竞争，合理

合理的高成本做局示例：
  ✓ 商会精心设局陷害主角——主角手里有商会急需的地契，合理
  ✓ 多方联手针对主角——主角的存在威胁到了多方共同的核心利益，合理

施压来源规则：

若主角是「无名小卒、无资源无威胁」阶段：
  ✓ 允许的施压来源：
      结构性困境（制度压迫、阶级壁垒、规则不公）
      环境压力（生存困境、天灾、时代背景）
      意外卷入（无意触碰某条线，被动卷入）
      误判压力（对方有合理理由误以为主角有价值）
  ✗ 禁止的施压来源：
      他人精心策划的针对性大局
      多方势力联合针对
      专门为了对付主角而设计的陷阱

若主角已「初步建立价值或威胁」阶段：
  ✓ 允许所有施压来源，但做局者的动机必须在节点描述里说清楚：
      做局者通过坑主角能得到什么？
      主角的哪一点让做局者觉得必须动手？

禁止：凭空出现没有动机说明的做局者。
```

### 2.1.1 新人物登场（利益驱动与伏笔）— 已并入 `path_gen.py`

在「禁止：凭空出现没有动机说明的做局者」之后，补充**人物凭空出现**的约束（与做局动机同属合理性范畴）：

```
新人物登场（利益驱动与伏笔）：
  在本节点之前，必须有一个细节埋下他出现的理由
    （哪怕只是一句话：老鬼说"王老板那边好像还请了别人"）
  禁止：新人物直接登场，没有任何前因
  人物出现的时机和方式必须能回答：
    他为什么这个时候出现？
    他从哪里得知这件事？
    他来这里对他有什么好处？
  若无法回答，则该人物不应在本节点首次登场，或需在前置节点补一笔伏笔。
```

## 三、`prompts/creation/expand1.py` 修改

### 3.1 antagonist 新增必填字段

在 `EXPAND1_OUTPUT_SCHEMA` 的 `who.characters` 里，对 `role=antagonist` 的角色新增约束：

```python
# EXPAND1_USER_TEMPLATE 的 who 分析部分补充：

对于 role 为 antagonist 的角色，motivation 字段必须回答以下两个问题：
  1. target_value：主角身上/行为中有什么让对方觉得值得针对？
     （资源/信息/地位/关系/威胁/挡路）
  2. antagonist_stake：对方不针对主角会失去什么？

如果这两个问题无法回答，说明当前节点不适合出现主动设局的反派，
应改为结构性困境或环境压力作为施压来源。

示例（合理）：
  target_value: "主角意外得知了账房做假账的证据"
  antagonist_stake: "账房若不消除主角，自己的罪行迟早暴露"

示例（不合理，需要改写）：
  target_value: "主角刚入职，什么都不知道"
  antagonist_stake: "无法说明"
  → 此时不应该有人精心设局，改为：新人被老员工欺负是常态（结构性困境）
```

同时在输出 Schema 里新增字段：

```python
"who": {
    "characters": [
        {
            "name": "str",
            "current_state": "str",
            "motivation": "str",
            "role": "protagonist|antagonist|bystander",
            # antagonist 专用，其他角色可以为空
            "target_value": "str",      # 主角身上什么值得被针对
            "antagonist_stake": "str",  # 不针对主角会失去什么
        }
    ]
}
```

## 四、`prompts/creation/synopsis.py` 修改

### 4.1 core_conflict 新增因果说明要求

在 `SYNOPSIS_USER_TEMPLATE` 里，`core_conflict` 的说明补充：

```
core_conflict 的描述必须包含：
  1. 冲突各方为何卷入（主角为什么会被牵扯进来）
  2. 若有反派或对立方，说明其针对主角的动机
     （通过针对主角能得到什么，或主角如何威胁其利益）
  3. 主角从弱到强的过程中，被针对的理由会随之变化
     （开篇被针对的理由 ≠ 中期被针对的理由）

禁止：只描述冲突结果，不说明冲突成立的前提。

示例（不合理）：
  "主角被各方势力追杀，在重重阻碍中逆境成长"
  → 没有说明为什么要追杀一个毫无价值的人

示例（合理）：
  "主角意外卷入一场走私案，成为唯一的目击证人，
   多方势力因此需要消灭他或利用他"
  → 清楚说明了主角被针对的具体原因
```
