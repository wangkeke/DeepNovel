# DeepNovel v4.3 · 补丁文档 B
## write 节点职责净化 × narrative_extract 独立提取节点

> **文档定位**：本文档是对 v4.3 终版架构文档的第二份补丁，
> 解决 write 节点职责混杂问题，新增 narrative_extract 独立提取节点。
> 合并时以本文档为准，覆盖 v4.3 终版文档中 write 节点和 bible_update
> 节点的对应部分，并在流程图中新增 narrative_extract。

---

## 一、问题诊断

### 当前 write 节点的职责混杂

write 节点目前同时输出三件事：

```
1. 正文（prose）          ← write 的本职
2. noun_foreshadows JSON  ← 信息提取，不属于 write
3. 本章事件路径链          ← 叙事摘要，不属于 write
```

这违反了节点职责单一原则，造成两个具体问题：

**问题一：质量互相干扰**

模型生成正文时处于叙事语感中，同时要求它输出结构化 JSON，
两种认知模式互相干扰——正文的文学感被格式约束拉低，
JSON 的提取精度也因沉浸在叙事语感中而降低。

**问题二：伏笔提取质量差的根本原因**

模型在刚写完正文、仍处于叙事语感时，
会倾向于把正文里出现过的所有名词都标注为潜在伏笔。
这是**名词扫描**而非**因果判断**。
第一章产生14条伏笔，其中约半数是功能道具或世界设定词条，
不是真正的伏笔，会在后续 event_chain_gen 中产生大量噪音。

### 根本解法

将信息提取工作从 write 节点剥离，放入独立的 narrative_extract 节点，
让模型以**分析者视角**而非**叙事者视角**做因果判断。

## 二、修订后的节点流程

```
旧流程：
write（正文 + noun_foreshadows JSON + 事件路径链）
  ↓
tension_check → auto_review → bible_update

新流程：
write（只输出正文）
  ↓
tension_check → auto_review
  ↓ 通过后
narrative_extract（叙事信息提取）
  ↓
bible_update（档案回写）
```

**关键设计**：narrative_extract 在正文通过 auto_review 之后才触发。
如果正文被打回重写，narrative_extract 不会运行，
避免对废稿做无效提取——当前方案中这是做不到的。

## 三、修订后的 write 节点提示词

**节点职责**：只生成正文，不做任何信息提取。

```
你是一位小说家。
你需要把 expand2 的场景方案写成正文。

你没有固定的写作公式需要遵守。
这一章是引爆节点，你就写出引爆的力道。
这一章是喘息节点，你就写出真实人类在松弛时刻的样子——
这往往是整部小说最有人味儿的段落，不要强行制造紧张感。

在动笔前确认以下六件事：

1. 这章的每个关键行动，是由角色的性格和处境驱动的，而非剧情需要
2. 破局涉及的资源，在前文有铺垫，不是凭空出现
3. 扣动关键行动的，是角色的精神层面，而非资源本身自动生效
4. 这章的结果，有一颗种子指向未来
5. 角色的成长，体现在行为差异上，不体现在内心独白的解释里
6. user_anchors 中的设定，没有被触碰

以上六件事是检查清单，不是写作公式。
确认通过后，忘掉这份清单，专注于写出这一章最真实的样子。

【输出格式】
只输出正文内容，不输出任何 JSON、标注或结构化信息。
正文结束即输出结束。
```

## 四、新增节点：narrative_extract — 叙事信息提取

**节点职责**：以分析者视角读取已通过审核的正文，
提取真正的伏笔和本章叙事路径链，供 bible_update 回写档案。

**触发条件**：正文通过 auto_review 之后触发，被打回的正文不触发。

**上游输入**：
- 已审核通过的正文全文
- path_gen 对本章路径的原始定义（用于路径链对比）
- karmic_ledger 当前状态（用于判断是否与已有伏笔重复）
- world_archive 中的势力和地点列表（用于排除背景知识）

```
你是一位资深编辑，刚刚读完了这一章的正文。
你现在切换到分析者视角，做两件事：
提取真正的伏笔，以及还原本章的叙事路径链。

━━━━━━━━━━━━━━━━━━━━━━━━━━━
第一件事：伏笔提取（因果判断，不是名词扫描）
━━━━━━━━━━━━━━━━━━━━━━━━━━━

【什么是真正的伏笔】

真正的伏笔满足以下全部三个条件：

条件一：在正文中以"不引起警觉"的方式出现
  初读的读者不会注意到它，或注意到了但不知道它意味着什么。
  如果读者第一遍就能猜到它的引爆方式，它不是伏笔，是预告。

条件二：在未来某个具体的事件类型中会以意想不到的方式成为关键因素
  你必须能说清楚：这个细节，大致会在什么类型的事件中引爆？
  （不需要精确到第几章，但必须有具体方向）

条件三：引爆时能产生"原来如此"的回头感
  回头重读这一章时，读者会发现"这里早就埋下了"。

【以下情况不是伏笔，不入库】

功能性道具：当前剧情正在解决的问题所需的道具。
  例：清蕴丹、续脉丹、缓毒散
  → 这是主角下一章就要处理的任务，不是未来的伏笔

世界设定的具体化：对世界物理规则的解释性词条。
  例：同源道蕴的定义、沉寂状态的解释、地脉节点的概念
  → 这是背景知识，不会在未来"引爆"

已在 world_archive 中注册的势力和地点：
  例：蚀骨荒原（世界地理）、灰蛇（已知势力）
  → 势力和地点本身不是伏笔，但它们的某个具体细节可以是

重复伏笔：与 karmic_ledger 中已有伏笔高度重合的内容
  → 不重复入库，在已有伏笔的 building_note 中追加本章新增的细节

【伏笔质量检验问题】

在决定入库之前，对每个候选伏笔问自己：

"如果我把这个细节从正文中删掉，
未来某个事件中会因为缺少它而产生明显的逻辑跳跃吗？"

如果答案是否（删掉也无妨），它不是伏笔，不入库。
如果答案是是，它才是真正的伏笔。

━━━━━━━━━━━━━━━━━━━━━━━━━━━
第二件事：本章叙事路径链还原
━━━━━━━━━━━━━━━━━━━━━━━━━━━

还原本章实际写出来的因果骨架——
不是你认为应该发生什么，而是正文中实际发生了什么。

格式：
行动1 → 行动2 → 行动3 → ... → 本章末尾状态

然后对比 path_gen 的原始路径定义：
- 如果实际路径与规划路径一致，标注：路径执行一致
- 如果实际路径与规划路径有偏差，标注偏差内容，
  并判断偏差是否合理（有机生长的自然漂移 vs 逻辑断裂）

⚠️ 路径偏差本身不是问题。
write 节点在执行过程中因真实档案状态而产生的有机漂移是正常的，
记录下来是为了让后续节点了解实际状态，而非要求路径严格对齐。

━━━━━━━━━━━━━━━━━━━━━━━━━━━
输出规范
━━━━━━━━━━━━━━━━━━━━━━━━━━━

{
  "foreshadows": [
    {
      "foreshadow_id": "伏笔唯一标识（格式：F章节号_序号）",
      "surface_appearance": "在正文中如何出现（引用原文相关句子）",
      "why_not_obvious": "为什么初读不会引起警觉",
      "estimated_payoff_type": "大致会在什么类型的事件中引爆
                               （如：身份揭露/背叛/能力觉醒/宿敌相遇等）",
      "retroactive_feel": "引爆时，回头看这个细节，读者会有什么感受",
      "karmic_ledger_action": "new（新增）/ update（追加到已有伏笔）",
      "update_target_id": "如果是update，填写已有伏笔的 seed_id；否则填null"
    }
  ],

  "chapter_path_chain": {
    "actual_chain": "本章实际叙事路径链（行动1 → 行动2 → ... → 末尾状态）",
    "planned_chain": "path_gen 原始规划的路径描述",
    "deviation_exists": true/false,
    "deviation_note": "如有偏差，描述偏差内容及判断（有机漂移/逻辑断裂）"
  }
}
```

## 五、修订后的 bible_update 伏笔处理

**修订位置**：v4.3 终版文档 → PROMPT 13 bible_update → karmic_ledger 更新

**修订内容**：bible_update 不再从正文中自行提取伏笔，
而是直接读取 narrative_extract 的输出结果，执行回写操作。

```
【karmic_ledger 更新（修订版）】

伏笔数据来源：
  不再从正文中自行提取，直接读取 narrative_extract 的 foreshadows 字段。

对每条 narrative_extract 输出的伏笔执行以下操作：

如果 karmic_ledger_action = "new"：
  在 karmic_ledger 中新增伏笔条目：
  {
    "seed_id": "foreshadow_id",
    "description": "伏笔内容（来自 surface_appearance）",
    "holder": "持有或涉及的角色/物品",
    "estimated_payoff": "estimated_payoff_type",
    "status": "latent（初始状态）",
    "chapter_planted": "当前章节号",
    "building_notes": []
  }

如果 karmic_ledger_action = "update"：
  找到 update_target_id 对应的已有伏笔，
  在其 building_notes 中追加本章的新细节，
  状态更新为 building，不新建条目。

【路径完成追踪（来自 narrative_extract 的 chapter_path_chain）】

记录本章实际执行的路径链（actual_chain），
与 path_gen 原始规划对比，如有偏差记录偏差原因。
这个信息注入 path_progress，供下一轮 event_chain_gen 参考。
```

## 六、修订后的完整章节循环流程

```
【章节循环（修订版）】

expand1（章节规划）
  ├─ 人工模式 → human_review_expand
  └─ 自动模式 → expand2

expand2（场景拆解）
  └─ write（只输出正文）
       └─ tension_check
            ├─ 需重写 → 回 write
            ├─ 自动审稿 → auto_review
            └─ 人工审稿 → human_review_write
                              ├─ 文字问题 → write
                              ├─ 场景问题 → expand2
                              └─ 方向问题 → expand1

auto_review / human_review_write 通过后：
  → narrative_extract（叙事信息提取）
       └─ bible_update（档案回写）
```

## 七、"本章事件路径链"的归属调整

当前方案：路径链在 write 节点输出，
作为 write 结果的附属信息展示给用户。

修订后方案：

```
路径链的生成：在 narrative_extract 中生成（actual_chain）
路径链的对比：在 narrative_extract 中与 path_gen 规划对比
路径链的展示：在 human_review_write 的审核界面中展示
              （用户看到的是 narrative_extract 生成的路径链，
              以及与规划的对比结果，而非正文生成时顺带产生的）
路径链的回写：在 bible_update 中写入 path_progress
```

这个归属调整的意义在于：
路径链现在是**对正文的事后分析**，而非**正文生成的附带产物**。
它能准确反映"这章实际发生了什么"，而不是"模型打算发生什么"——
两者在有机漂移发生时会产生差异，这个差异是有价值的信息。

## 九、设计决策记录

### 9.1 为什么伏笔提取必须独立于正文生成？

叙事模式（生成正文）和分析模式（因果判断）是两种不同的认知状态。
要求模型在同一次调用中同时处于两种状态，两者都会打折扣。

更重要的是：在正文生成阶段，模型不知道哪些细节会通过审核。
如果正文被打回重写，之前提取的伏笔信息就是废弃的——
而独立节点只在正文通过审核后触发，确保所有提取都基于"真正写进书里的内容"。

### 9.2 为什么伏笔判断标准是"删掉是否产生逻辑跳跃"？

这个标准来自经典叙事理论中的"契约性细节"概念——
只有那些在未来事件中被引用、且缺少时会产生逻辑断裂的细节，
才是真正构成叙事合同的伏笔。

名词扫描式的伏笔提取（把所有有趣的词语都标注为伏笔），
会导致 karmic_ledger 膨胀，后续 event_chain_gen 在读取未引爆伏笔时，
面对的是一个充满噪音的账本，而不是真正有价值的因果线索。

### 9.3 路径偏差为什么不是问题？

write 节点在执行时读取的是当前真实的档案状态，这个状态可能与
path_gen 规划时的状态有所不同。有机生长带来的轻微漂移是正常的，
记录下来是为了让后续节点了解实际状态——

如果 narrative_extract 持续发现严重的路径偏差，
说明 path_gen 的规划与当前档案状态之间存在系统性的断层，
需要检查 bible_update 的回写是否完整。

## 十、与 v4.3 终版文档的对照变更说明

| 节点 | 变更类型 | 核心变更内容 |
|------|---------|------------|
