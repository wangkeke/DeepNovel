# DeepNovel 小说骨骼系统设计文档
> 理论体系与实现逻辑
> 仅描述逻辑，不涉及代码实现

---

## 一、核心理论：小说的底层结构

### 1.1 故事节点的本质

小说由若干**故事节点**组成。

故事节点不是一个孤立的事件（"张三被打了"），而是一个**相对完整的故事弧**——有起因、有发展、有高潮、有结果，人物在节点结束时的状态真实改变于节点开始时的状态。

每个故事节点内部有一条或多条**逻辑链**驱动。逻辑链是节点能够"成立"的因果结构：为什么这件事发生在这个人身上、为什么是现在、为什么会有这个结果。

人物、地点、时间、事件不是独立存在的标签，而是逻辑链的**参数**。改变任何一个参数，逻辑链的走向就会不同。

**节点的规模由逻辑完整性决定，不由字数决定。**

节点存在三个层级，与分形结构对应：

| 层级 | 典型规模 | 示例 | 用途 |
|---|---|---|---|
| 宏观节点 | 2万-5万字 | "林冲被逼上梁山"整个故事弧 | 全书结构划分 |
| 中观节点 | 5000-2万字 | "陆谦火烧草料场" | **骨骼提取和创作路径的基本单位** |
| 微观节点 | 2000-5000字 | "林冲在酒馆忍住没动手" | 扩写阶段自然产生，不单独列入路径 |

系统中说的"故事节点"默认指**中观节点**。它在逻辑完整性和处理成本之间平衡最好：对骨骼提取来说不超出单次处理窗口，对创作来说用户确认路径清晰可读，扩写后每节点产出800-2000字正文质量可控。微观节点的内容在扩写阶段（第一轮3W1H、第二轮场景设计）自然生成，不需要单独规划。

### 1.2 节点之间的连接

节点与节点之间的关系不是"然后发生了"，而是**因果传导**：

- 每个节点有**输入状态**（接收前一节点的输出）
- 每个节点有**输出状态**（成为后一节点的触发条件）
- 前节点的输出状态必须能自然推导出后节点逻辑链的起点

连接本身也是逻辑，而不仅仅是时间顺序。

### 1.3 三层分形结构

逻辑链在三个层级上同时存在，且结构自相似：

```
宏观层（全书）
  多条故事线汇聚 → 触发最终高潮 → 世界/人物终极状态改变

中观层（故事弧）
  多个节点的输出汇聚 → 触发更大的临界点 → 更大的状态改变

微观层（节点内部）
  多股力量作用于人物 → 触发临界点 → 状态改变
```

**关键推论**：一部小说的"气质"之所以贯穿始终，是因为同一条逻辑链类型贯穿了三个层级。压抑的小说在每个微观节点里也是压抑的；爽文在每个小节点里也能给读者爽感。这不是巧合，是分形结构的必然结果。

## 二、逻辑链的分类

不同类型的小说，核心逻辑链类型不同。这些类型是小说"气质"的本质来源。

**逻辑链类型分为两大类：施压链与破局链。**

施压链描述冲突如何形成和升级，破局链描述冲突如何被解决或逆转。一个完整的故事节点通常包含一条或多条施压链，加上一条破局链，两者缺一不可。只有施压没有破局，故事会陷入死局；只有破局没有施压，故事会失去张力。

在节点的逻辑链记录里，每条逻辑链需要标注当前用于施压还是破局。

**施压链（推动冲突形成）：**

| 类型名 | 核心机制 | 常见题材 |
|---|---|---|
| 间接施压型 | 通过第三方或弱点达成目的，主谋不直接出手 | 宫斗、商战、权谋 |
| 多源汇聚型 | 无单一主谋，多股力量独立施压，合力压垮主角 | 底层逆袭、武侠被逼出山 |
| 资源争夺型 | 多方争夺同一稀缺资源，每方行动互相影响 | 玄幻争宝、商业并购 |
| 蝴蝶效应型 | 微小起因经多次传导引发巨大结果 | 历史架空、社会派 |
| 自我实现困局型 | 主角越试图逃脱，越把自己推向深渊 | 悲剧、黑色电影 |
| 信任背叛链型 | 建立信任→被利用→反噬，或背叛引发连锁 | 言情、兄弟情仇、职场 |

**破局链（解决或逆转冲突）：**

| 类型名 | 核心机制 | 常见题材 |
|---|---|---|
| 信息差破局型 | 掌握他人不知道的关键信息，由此获得主动权并反压 | 重生爽文、谍战、商战 |
| 以弱胜强型 | 主角在力量劣势下，利用规则/地形/时机完成逆转 | 武侠、底层逆袭 |
| 揭露反转型 | 隐藏信息被暴露，导致力量对比瞬间改变 | 悬疑、宫斗、谍战 |
| 借力打力型 | 将对手的施压力量反向利用，让施压者自食其果 | 权谋、商战 |
| 知识技能破局型 | 用专业知识或特定技能解决看似无解的困境 | 民俗恐怖、硬科幻、探险 |
| 纯推理型 | 已知线索推导唯一真相，逻辑严密有唯一正确答案 | 本格推理、硬派悬疑 |

**重要说明**：真实小说往往是多种类型的组合，识别的目的是理解结构，不是贴唯一标签。信息差类型在施压和破局两侧均可出现，记录时需标注方向（是主角掌握优势还是对手掌握优势）。

## 三、小说骨骼的三层构成

从范文中提取的"骨骼"分为三层，每一层回答不同的问题：

### 第一层：结构模板（Structure Template）
**回答：这部小说是怎么组织的**

- 宏观节奏：开篇几个节点建立世界观、几个节点引入主要矛盾
- 卷/章结构：几卷、每卷几个故事节点、每节点大概字数
- 故事线数量：主线加几条副线、副线何时汇入主线
- 人物关系格局：谁是核心、谁是对立面、谁是工具人、谁是隐藏变量
- 场景分布：主要发生在哪几个场景、场景之间怎么切换
- 伏笔密度：平均多少个节点埋一个伏笔、多少个节点后回收

### 第二层：逻辑规律（Logic Pattern）
**回答：这部小说为什么好看**

- 爽点节奏：多久给读者一个爽点（打脸、逆袭、升级）
- 冲突升级方式：对手强度怎么递进、主角如何破局
- 情绪曲线：紧张→舒缓→更紧张的节奏是怎么设计的
- 转折手法：意外反转前有哪些铺垫信号
- 读者预期管理：什么时候满足预期、什么时候打破预期

### 第三层：逻辑链图谱（Logic Chain Map）
**回答：这部小说的因果架构是什么**

这一层是骨骼中最核心也最难提取的部分。

**每个故事节点的逻辑链记录**：

```
节点名称：林冲被逼上梁山

【事件路径链】（骨骼中最核心的可复用部分）
  1. 高衙内看上林冲娘子，仗势欺人强行调戏 → 林冲被迫当众隐忍，尊严受损
  2. 林冲告状，高俅以权压制，申诉渠道被封死 → 体制证明自己不是盟友
  3. 高俅设计陷害，林冲误带刀入白虎节堂 → 被定为刺杀罪，流配沧州
  4. 陆谦奉命追杀，火烧草料场 → 连最信任的人都是敌人，旧世界彻底没有退路
  5. 林冲手刃仇敌，主动斩断最后一根退路 → 完成从"被迫承受"到"主动决裂"的转变

【施压源分解】
  · 高衙内：欲望驱动，主动施害（不知道其他施压源的存在）
    施压手段：以权势制造不可对抗的情境
    为何无法化解：正面反抗等于以卵击石，忍耐又被误读为软弱
  · 高俅：权力庇护，系统性支撑（与高衙内直接关联）
    施压手段：封死体制内的申诉出口
    为何无法化解：他就是那个"规则本身"
  · 陆谦：信任背叛，致命一击（独立施压，林冲最相信的人）
    施压手段：以友情为掩护，充当棋子执行追杀
    为何无法化解：无从防备，信任本身是漏洞
  · 体制结构：环境性压迫（不是个人，是结构）

【主角制约条件】
  · 有家有业不敢轻易离开（有所顾忌）
  · 每次忍耐都被误读为软弱，反而加剧施压
  · 申诉渠道被封死，体制不是盟友

【临界事件】
  陆谦背叛——连最信任的人都靠不住，旧世界里已没有任何锚点

【逻辑链类型】（从以上路径归纳）
  施压链：多源汇聚型（多方独立施压，林冲无法一次性应对全部）
  破局链：以弱胜强型（在绝对劣势下，靠主动决裂而非反制完成转变）

节点输出状态：
  林冲彻底与旧世界决裂，带着仇恨和顶级战力，无路可退
```

> **使用说明**：另一个作者可以把林冲换成任何人物，把高俅换成任何权力结构，但沿着"忍耐→体制失效→信任崩塌→主动决裂"这条事件路径，可以生长出完全不同的故事。事件路径是骨骼中真正可以被"偷走"的部分，逻辑链类型标签只是对这条路径的归纳总结。

**逻辑链中特别需要记录的要素**：

伏笔地图——每个关键信息的"双重含义"：
```
信息：书房里有一束花
  表面含义（读者当时理解）：主人讲究品位
  真实含义（回头看）：凶手提前布置的道具
  埋入位置：第3节点
  回收位置：第22节点
  误导方向：让读者注意到书房主人的性格
```

## 四、范文提取的完整流程

### 4.1 输入来源

支持三种来源，优先级依次降低：

1. **用户指定目录**：用户提供的本地文件（txt/docx/pdf/图片OCR）
2. **用户指定网址**：爬取对应网页内容
3. **系统内置库**：按题材分类存储的已有骨骼，无需重新提取

### 4.2 全量文本处理

**处理原则：不跳过、不截断，对原文进行完整遍历。**

部分采样会导致逻辑链在提取阶段就出现断口。一部悬疑小说第3章埋的伏笔第58章才回收，如果采样时跳过了第3章，这条伏笔就永远丢失了。全量处理是保证逻辑链完整的唯一方式。

**处理方式：滑动窗口遍历 + 累积合并**

```
完整原文（无论多少字）
        ↓ 按故事节点或章节切分
[第1-N节点]  → 提取局部骨骼信息 → 写入临时存储
[第N+1-M节点]→ 提取局部骨骼信息 → 写入临时存储
[第M+1-...节点]→ 提取局部骨骼信息 → 写入临时存储
...（遍历全书，不跳过任何节点）
        ↓ 全部批次处理完毕
合并所有临时存储 → 完整骨骼档案（NovelBlueprint）
        ↓
全局规律提炼（基于完整合并结果做最后一次整体分析）
```

每批处理约5000字，30万字的小说约60批次。骨骼提取只做一次，之后可以反复复用，这个代价是值得的。

**切分原则：按中观节点边界切分，不按字数**

不按固定字数硬切，而是按中观节点边界切分。中观节点通常对应1-3章，是一个有完整逻辑链（有输入状态、内部逻辑、输出状态）的故事单元。选择中观节点而非章节的原因：

- 单章（微观节点）太细：逻辑链经常跨章延伸，按单章切会切断一条完整的因果链
- 宏观节点太粗：一个宏观节点可能跨2-5万字，超出单次处理窗口
- 中观节点：逻辑链完整，字数适中（5000-2万字），不会超出窗口也不会切断逻辑

**节点边界的判断依据：输出状态是否改变**

字数范围只是初步筛选，真正的节点边界判断依据是：**这一章结束时，主角的身份/处境/关系是否发生了本质改变？**

- 如果没有改变 → 逻辑弧尚未完成，应与下一章合并
- 如果已经改变 → 确认为节点边界

这个判断比字数更可靠。以《邪门儿》为例：第1章结束时主角还没遇到师父（逻辑弧未完），第1章和第2章必须合并为同一个中观节点"土匪师爷"；第3章结束时主角完成了入门仪式（身份本质改变），第3章自成一个节点"拜石入门"。如果按章节简单切分，第1章会被单独切出，导致"师徒关系建立"这条逻辑链在节点内部断裂。

每批处理开始时，提示词必须包含前一批次的延续上下文：
- 前一批次结束时的人物状态
- 前一批次结束时悬而未决的线索
- 前一批次的尾部输出状态

这是保证跨批次逻辑链齿轮咬合的关键机制。

**三遍处理流程：**

Pass 1a（正向遍历，叙事提取，逐批进行）：
- 提取事件路径链：4-8条，每条格式为"{谁}{做了什么/发生了什么}→{直接结果}"，具体到可被套用的情节动作，不是主题归纳
- 提取施压源分解：每个施压源的具体手段 + 主角为何无法正面化解
- 记录临界事件：哪一条具体事件触发了力量对比改变
- 记录节点输入/输出状态
- 更新全局实体注册表（见下方说明）
- 此阶段不要求识别伏笔——正向阅读时无法判断哪些是伏笔

Pass 1b（在 Pass 1a 结果上做结构标注，逐批进行）：
- 基于 Pass 1a 提取的事件路径，归纳施压链类型和破局链类型
- 类型标注附在路径上，作为归纳结论，不能替代路径描述本身
- 此步骤的输入是 Pass 1a 的结构化结果，不是原文，成本较低

全局汇总（Pass 1 全部完成后）：
- 基于所有批次的摘要，生成结构化真相清单
- 真相清单的格式：谁是关键人物、做了什么、动机、手法、关键时间节点、需要在前文找的早期暗示方向
- 真相清单是结构化数据，不是叙述性大纲

Pass 2（带真相清单逆向扫描，逐批进行）：
- 将真相清单作为上下文，重新扫描每一批次
- 提示词逻辑："已知以上真相，请在本批文本中找出能作为任何一条真相的早期暗示的信息，并说明它的表面含义和真实含义、对应的真相条目、以及它的误导方向"
- 此阶段专门提取伏笔地图，不重复提取其他信息

Pass 3（跨批次汇总与全局规律提炼）：
- 合并 Pass 1 的逻辑链序列，拼接完整因果链
- 合并 Pass 2 的伏笔地图（含跨度极长的伏笔）
- 识别跨批次的施压源关系
- 生成完整人物关系图和场景分布
- 统计全书宏观规律：爽点间隔、情绪曲线形态、伏笔密度

**全局实体注册表：**

跨批次处理时，同一实体可能以不同称谓出现。注册表覆盖三类实体，不只是人物：

- **人物实体**：同一角色可能有姓名、绰号、称谓等多种叫法（"高俅"/"高太尉"/"老高"）
- **地点实体**：关键场景可能有正式名称和民间叫法（"歪脖子老槐树"/"鬼树"/"阵眼"）
- **道具/组织实体**：重要物件或门派也会出现名称漂移（"石头人"/"祖师爷像"/"石嘴"）

```
实体注册表每条记录：
  标准名：高俅
  实体类型：人物 / 地点 / 道具 / 组织
  已知别称：["高太尉", "老高", "太尉"]
  首次出现批次：第2批
  身份标签：反派、官员
  关联实体：高衙内（父子关系）
```

每批新提取的实体，先做别称字符串匹配，匹配失败后再用模型判断是否与注册表中已有实体为同一个。两步走比单纯依赖模型判断更可靠。

**标准名选取规则（优先级从高到低）：**

| 优先级 | 来源 | 处理方式 | 示例（《邪门儿》） |
|---|---|---|---|
| 1 | 其他角色稳定使用的称呼或绰号 | → 做标准名 | 老核桃 → standard_name |
| 2 | 有历史来源的称号 | → 做别称（alias） | 土匪师爷 → alias |
| 3 | 关系称谓（师父/大哥/娘子） | → 进 related_entities，绝不做标准名 | "师父" → relation |
| 4 | 叙述者口语化称呼（老头儿/那家伙） | → 进 role_tags，不进 aliases | "老头儿" → role_tags |

**别名收录标准：**

别名必须同时满足以下两个条件才能收录：
1. **可替换性**：这个称呼可以替换标准名，唤起的是同一个人，不会产生歧义
2. **稳定性**：这个称呼在多个场合被稳定使用，不是一次性的情绪表达

按此标准，以下类型不应收录进别名字段：

| 类型 | 示例 | 原因 | 正确处理 |
|---|---|---|---|
| 骂人话/情绪化表达 | "老东西"、"死胖子" | 表达情绪，不是稳定身份标识 | → role_tags |
| 一次性自嘲/自称 | "老骨头"（自嘲） | 上下文相关，不可替换使用 | → role_tags |
| 身份描述/标签 | "老江湖"、"武力天花板" | 描述特征，不是称呼 | → role_tags |
| 关系称谓 | "师傅"、"大哥" | 叙述者视角称呼，不是实体标识 | → related_entities |
| 叙述者口语称呼 | "老头儿"、"那小子" | 带主观视角，不是客观标识 | → role_tags |

**第一人称叙述的特殊处理：**

第一人称小说中，"我"是叙述视角的标记，不是任何角色的别名。

处理规则：
- "我"不收录进任何人物的别名字段
- 主角的标准名以文中其他角色对其的称呼为准
- 若全文从未出现主角真名，标准名暂定为"主角（我）"，并在身份标签中注明"第一人称叙述者"
- 遇到"我说"、"我看见"等叙述句时，提取的是主角作为人物的行为，不是"我"这个词作为称谓

**第一人称叙述中的实体识别验证：**

第一人称小说中存在一个特殊风险：把叙述者"我"观察的对象错认为叙述者本身。提取时必须主动验证每个具名人物的身份：

- 如果文中存在"我看见 X……"、"我跟着 X……"这类句子，X 被"我"以第三人称观察，X 就不是叙述者
- 只有从未被"我"以第三人称观察、所有第一人称行动都能归属的人物，才可能是叙述者

以《邪门儿》为例：高大头是第一章最先出场的具名人物，但文中有"我看见高大头……"的句子，说明高大头是被叙述者观察的对象，不是叙述者本人。错误地把高大头识别为"主角（我）"，会导致整个实体注册表的身份关系错乱。

**片段文本的处理边界：**

Pass 2（伏笔逆向扫描）依赖完整的真相清单，而真相清单需要全书 Pass 1 完成后才能生成。因此：
- 完整文本：三遍处理全部可执行，伏笔地图完整可靠
- 片段文本：只能完成 Pass 1，伏笔地图只能基于可见上下文推断，会有缺失，需标注"片段提取，伏笔不完整"

### 4.3 提取内容的分层说明

**4.2 与 4.3 的关系：**

4.2 描述的是**执行机制**（三遍处理的顺序和方式），4.3 描述的是**提取内容的分层**（每一层提取什么）。两者是交叉关系：

```
Pass 1a 执行时，提取：事件路径链 + 施压源分解 + 实体注册表 + 第一层内容 + 第二层内容（除伏笔外）
Pass 1b 执行时，标注：逻辑链类型（基于 1a 结果归纳）
Pass 2  执行时，专门提取：第三层内容（伏笔地图）
Pass 3  执行时，汇总生成：完整的三层骨骼档案
```

**第一层提取内容**（在 Pass 1 中完成）：
- 宏观节奏：切入方式、节奏模式、各阶段划分
- 卷章结构：故事节点数量、每节点字数估算
- 故事线数量和汇聚方式
- 场景分布：主要场景及其作用

**第二层提取内容**（在 Pass 1 中完成）：
- 爽点节奏：多少节点出现一次爽点，爽点的类型
- 冲突升级方式：威胁如何递进
- 情绪曲线模式：紧张与舒缓的交替规律
- 转折手法：反转前的铺垫信号特征

**第三层提取内容**（Pass 1a/1b 提取路径和类型，Pass 2 补充伏笔）：

逐节点的逻辑链记录，每个节点包含：

- **事件路径链**（★ 核心字段，Pass 1a 完成）：4-8条按因果顺序排列的具体事件，每条格式为"{谁}{做了什么/发生了什么}→{直接结果}"。这是骨骼中真正可以被套用的部分——另一个作者可以把人物和场景全换掉，但沿着相同的事件路径生长出完全不同的故事
- **施压源分解**（Pass 1a 完成）：每个施压者的具体手段 + 主角为何无法正面化解，不是类型标签而是行为描述
- **临界事件**（Pass 1a 完成）：哪一条具体事件触发了力量对比改变
- **逻辑链类型**（Pass 1b 完成）：基于事件路径归纳的施压链类型和破局链类型，支持复合写法，单一节点内施压和破局分别标注，附上在路径中对应的是哪几个事件
- 节点输入状态 / 输出状态（Pass 1a 完成）
- 伏笔记录：本节点埋入的伏笔（Pass 2 填充）

**节点连接映射**（在 Pass 3 中完成）：

仅记录节点间的因果连接，补充在逻辑链图谱里：

```
节点连接记录示例：
  从节点：林冲被逼上梁山
  到节点：梁山接纳林冲
  连接逻辑：林冲的到来（绝望+顶级战力）恰好成为王伦与晁盖之间
            权力博弈的催化剂，触发了梁山内部的洗牌
  连接类型：输出状态触发新节点的内部矛盾
```

这个字段解决"节点之间的连接本身也是逻辑"在骨骼档案里没有对应记录的问题。

三层内容全部提取完成后，合并形成完整的 NovelBlueprint（小说骨骼档案）。

## 五、骨骼在创作中的使用

### 5.1 基本原则

骨骼是创作的**锚点**，不是**模板**。

- 骨骼的作用：防止逻辑断裂，提供结构参考
- 骨骼不能做的：决定内容是什么、替代创作判断
- 骨骼随创作生长：原创内容有权改变骨骼，骨骼记录这个改变

### 5.2 三种使用方式

**方式一：借用结构，内容自创（最常用）**

取骨骼中某个节点的逻辑链类型，新小说的内容完全重新设计。

骨骼提供的是：这个位置需要一个"多源汇聚→临界爆发"的节点
创作提供的是：具体是哪几个压力源、爆发时发生了什么

**方式二：插入原创节点**

骨骼提供主干节点，在节点之间插入完全原创的故事弧。

原创节点的插入不是随意的，它必须：
- 接收前一骨骼节点的输出状态
- 将修改后的输出传递给下一骨骼节点
- 导致下一骨骼节点的含义因此改变（这就是插入的意义）

**方式三：扭转骨架（高级，有前置条件）**

在某个关键节点，新小说选择和骨骼完全不同的走向。

扭转必须满足前置条件，否则不触发：
- 人物性格和前面的剧情发展，使得骨骼的走向变得不合逻辑
- 用户明确指定要走不同的方向

扭转的理由必须被明确记录。后续的一致性检查以这个理由为依据，而不再对照原始骨骼内容。

### 5.3 扭转后的参考机制

扭转发生后，对骨骼的参考方式必须切换：

**扭转前**：参考骨骼的结构 + 内容走向

**扭转后**：只参考骨骼的**结构序列**，完全放弃内容走向

具体来说：
- 扭转点之后，骨骼的内容（谁做了什么）不再参考
- 骨骼中节点的逻辑链类型序列（什么类型→什么类型）仍然参考
- 新小说用这个类型序列，但内容由当前实际状态决定

示例：
```
骨骼原始：C（信任背叛）→ D（信息差）→ E（爆发）
在C处扭转后，新小说走向C'

C'之后的参考：
  不再参考D的内容（D是骨骼里的张三背叛事件）
  继续参考结构序列：下一个节点应该是"信息差型"，再下一个是"爆发型"
  至于信息差的内容是什么、谁爆发——完全由新小说的当前状态决定
```

## 六、一致性检查体系

### 6.1 三条检查依据

创作过程中，一致性检查的依据来自三个来源：

**依据一：新小说内部的一致性**（故事圣经）
- 人物的当前状态与前文是否连续
- 已埋的伏笔是否有对应的回收计划
- 人物动机前后是否自洽
- 这是故事圣经（BibleIndex）一直在做的事，扭转前后都适用

**依据二：结构序列的一致性**（来自骨骼）
- 骨骼提供的逻辑链类型序列是否在新小说中得到体现
- 不检查内容是否相同，只检查结构类型是否匹配
- 例：骨骼说这里应该有一个"背叛节点"，检查新小说是否存在背叛逻辑，不管背叛者是谁

**依据三：扭转逻辑的延续性**（仅扭转后适用）
- 扭转点C'的输出状态
- 后续节点的逻辑链起点必须能从C'的输出状态自然推导
- 这是纯内部逻辑检查，与骨骼无关

### 6.2 检查不应拦截的情况

骨骼的唯一职责是防止逻辑断裂，不是防止意外或创新：

**应该保留的"意外"**：
- 主角做了骨骼没预料到的选择，但有充分的人物逻辑支撑
- 处理方式：记录这个变化，更新骨骼的实际状态

**应该拦截的断裂**：
- 某个节点的逻辑链起点无法从前一节点的输出状态推导
- 已埋伏笔没有对应的回收节点
- 人物在没有理由的情况下动机突变

## 七、全流程设计

### 7.1 完整创作流程

```
用户提供题材和范文来源
        ↓
【范文获取】
  用户指定目录/网址 → 读取/爬取
  未指定 → 从骨骼库匹配同类型
        ↓
【全量文本处理】
  按故事节点/章节切分，滑动窗口遍历全文，不跳过任何内容
  第一阶段：逐批次提取局部骨骼信息，写入临时存储
  第二阶段：全部批次完成后跨批次汇总，合并伏笔地图和人物关系
  第三阶段：全局规律提炼，生成宏观逻辑链统计
        ↓
【骨骼提取】（三次分层提取，基于全量处理结果）
  第一次：逻辑链类型 + 宏观结构
  第二次：逐节点逻辑链分解
  第三次：完整伏笔地图（含跨度极长的伏笔）
  → 生成 NovelBlueprint，存入骨骼库
        ↓
【宏观构思】（参考骨骼的第一层和第二层）
  生成：标题 + 世界观 + 主角设定 + 核心冲突 + 大致走向
  字数：300字以内，只说骨干
        ↓
【用户确认宏观构思】← 第一次人工介入
  满意 → 继续
  修改 → 调整后重新确认
        ↓
【故事路径生成】（参考骨骼的逻辑链图谱）
  生成10个左右的故事节点（中短篇：全部；长篇：第一批）
  每个节点携带：逻辑链类型、建议的人物/地点参数
        ↓
【用户确认故事路径】← 第二次人工介入
  满意 → 进入创作
  修改 → 调整后重新确认
        ↓
【逐节点全自动创作循环】
  对每个节点：
    第一轮扩写（3W1H + 状态更新）
    第二轮扩写（场景设计，注入骨骼逻辑规律）
    正文写作（注入骨骼写作风格 + 伏笔植入指令）
    故事圣经更新
    一致性检查（三条依据）
        ↓
【长篇续写循环】
  一批节点完成 → 基于当前状态自动生成下一批节点路径
  骨骼参考权重逐渐降低，新小说的实际状态权重逐渐提高
        ↓
【写作完成，交付用户】
```

### 7.2 骨骼的注入时机

骨骼不是在所有阶段都注入，不同阶段注入不同层：

| 创作阶段 | 注入的骨骼层 | 注入的内容 |
|---|---|---|
| 宏观构思 | 第一层（结构模板）+ 第二层（逻辑规律） | 卷章结构、爽点节奏、情绪曲线方向 |
| 故事路径生成 | 第三层（逻辑链图谱）的类型序列 | 逻辑链类型、节点连接方式 |
| 第一轮扩写 | 不注入骨骼 | 只参考故事圣经和前节点状态 |
| 第二轮扩写 | 第三层的逻辑规律部分 | 冲突升级方式、转折手法 |
| 正文写作 | 第一层的写作风格 + 伏笔植入指令 | 语言风格、需要在此节点埋入的伏笔 |
| 一致性检查 | 全部三层 | 作为检查依据，不作为生成内容 |

### 7.3 骨骼权重的动态变化

骨骼对创作的影响力不是固定的，应该随创作推进动态调整：

```
创作初期（前20%节点）：
  骨骼权重高
  新小说还没有足够的自身积累
  需要骨骼提供更多结构支撑

创作中期（20%-70%节点）：
  骨骼权重中等
  新小说已经有了自己的人物状态、伏笔积累
  骨骼和实际状态各占一半参考权重

创作后期（70%-100%节点）：
  骨骼权重低
  新小说已经高度个性化
  主要参考自身的故事圣经和伏笔回收需求
  骨骼只作为兜底的结构检查依据
```

## 八、骨骼库的管理

### 8.1 骨骼档案的存储维度

每份骨骼档案（NovelBlueprint）存储以下信息：

```
基本信息：
  骨骼ID、来源标题（如知道）、题材标签、来源类型

第一层（结构模板）：
  宏观节奏描述
  卷章结构数据
  故事线数量和汇聚方式
  人物关系格局
  场景分布
  伏笔密度统计

第二层（逻辑规律）：
  爽点节奏描述
  冲突升级方式
  情绪曲线模式
  转折手法描述
  写作语言风格（原有字段）
  写作技巧（原有字段）

第三层（逻辑链图谱）：
  每个故事节点的逻辑链记录
  逻辑链类型序列（全书）
  伏笔地图
```

### 8.2 骨骼匹配策略

当用户未提供范文时，从骨骼库中匹配：

```
匹配优先级：
  1. 题材完全匹配（都市重生 → 找都市重生骨骼）
  2. 逻辑链类型匹配（用户说"要有背刺和反转" → 找含信任背叛型的骨骼）
  3. 宏观情绪匹配（用户说"要爽" → 找爽点密度高的骨骼）
  4. 以上都没有 → 使用通用骨骼（已验证的基础结构）

匹配结果可以是多个骨骼的组合：
  宏观结构来自骨骼A
  逻辑链类型序列来自骨骼B
  伏笔风格来自骨骼C
```

### 8.3 骨骼组合兼容性检查

多骨骼组合看似灵活，但骨骼之间存在隐含耦合——不同题材的世界规则不同，一个骨骼里合理的破局方式，在另一个骨骼的世界规则下可能完全失效（武侠里"凭武力单挑解决问题"是合理的，放进宫斗世界就失效了）。

组合前必须检查三个维度的兼容性：

**维度一：世界规则类型**

| 类型 | 说明 | 代表题材 |
|---|---|---|
| 现实规则 | 破局手段受真实世界约束，无超自然 | 都市、历史、职场 |
| 超自然规则 | 允许超现实破局手段，有明确的力量体系 | 玄幻、修仙、科幻 |
| 混合规则 | 有限度的超自然，民间信仰和现实共存 | 民俗恐怖、武侠、传奇 |

来自不同世界规则类型的骨骼，破局链可能互不相容。**现实规则骨骼与超自然规则骨骼不可直接混用。**

**维度二：冲突规模**

| 规模 | 说明 | 代表题材 |
|---|---|---|
| 个人级 | 冲突影响范围是个人关系和命运 | 言情、职场、家庭 |
| 组织级 | 冲突影响范围是群体利益和权力结构 | 宫斗、商战、帮派 |
| 世界级 | 冲突影响范围是文明、国家或世界 | 史诗玄幻、历史架空 |

宏观结构来自世界级骨骼、逻辑链来自个人级骨骼，会产生规模错位——宏观叙事要求史诗感，但每个节点的冲突动机只是个人恩怨，读者会感到失调。**跨越两个规模层级的组合需要特别说明过渡机制。**

**维度三：主角力量定位**

| 定位 | 说明 | 代表题材 |
|---|---|---|
| 主角弱势型 | 压迫者天然强于主角，主角靠智谋/运气求生 | 逼上梁山、底层逆袭 |
| 主角强势型 | 主角天然掌握优势，核心爽感来自碾压 | 重生爽文、无敌流 |
| 势均力敌型 | 双方实力接近，靠信息和谋略分胜负 | 谍战、商战、对手型悬疑 |

弱势型宏观结构配上强势型破局逻辑链，前半段读者代入了弱者视角，后半段主角突然变成碾压姿态，节奏感会断裂。**力量定位不同的骨骼组合前，需要设计一个明确的"力量转折点"节点来衔接。**

**兼容性检查结论：**

```
可以直接组合：
  同一世界规则类型 + 相邻冲突规模 + 相同力量定位

需要过渡设计后才能组合：
  相邻世界规则类型（现实+混合，或混合+超自然）
  跨一个冲突规模层级
  不同力量定位（需设计力量转折点）

不建议直接组合：
  现实规则 + 超自然规则（破局机制根本不相容）
  跨两个冲突规模层级（叙事焦距无法统一）
```

## 九、理论边界与局限

以下能力目前在理论和实现上均有明确边界：

**系统能做到的**：
- 从范文中提取三层骨骼结构，存储为可复用的参考档案
- 在创作时按照骨骼的结构序列生成逻辑自洽的故事路径
- 有计划地在指定节点埋入和回收伏笔
- 检测并拦截逻辑断裂
- 在扭转发生后维护双参考体系的一致性

**系统做不到的，需要人工把关的**：
- 极高精度的谜题设计（《名侦探柯南》级别的密室逻辑）
- 保证伏笔足够隐蔽不被读者提前识破
- 扭转点本身的创作质量（扭转的理由写得好不好）
- 多骨架融合时的融合质量（哪两个骨架能产生化学反应）

**关于模型能力的边界**：
- 提示词无法独立维持跨节点的状态记忆，所有状态必须由系统显式管理
- "只取结构不取内容"这类抽象指令对小模型不可靠，需要通过系统拆分为具体指令
- 骨骼的存在不是为了弥补模型能力的不足，而是为创作提供逻辑锚点，即使强模型也需要这个锚点
